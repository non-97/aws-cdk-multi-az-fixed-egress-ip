aws-cdk-multi-az-fixed-egress-ip

異なる AZ にあるクライアントから、送信元 IP を 1 つしか許可しない接続先サーバーへ、 常に単一の固定送信元 IP で通信しつつ Multi-AZ 可用性を保つための AWS 環境を CDK で構築する。

解きたい課題

接続先サーバー(外部の連携先)は 送信元 IP を 1 つだけ ホワイトリスト登録できる。 一方、こちら側のクライアントは 可用性のため複数 AZ に分散している。 プライベート IP は サブネット = AZ に固定されるため、そのままでは「AZ ごとに別の送信元 IP」になり 1 IP 制約を満たせない。

ゴール: どの AZ のクライアントから出ても送信元は常に 10.10.0.85、かつ AZ 障害に耐える。

中核アイデア

VIP を ENI に固定しない

固定送信元 IP 10.10.0.85 はどの ENI にも割り当てず、SNAT の masquerade 送信元かつ専用 /28 サブネットの中身として扱う。

戻りは VGW でサブネット単位に向ける

戻り(宛先 .85)は VGW のゲートウェイルートテーブルで 10.10.0.80/28 → 現用 SNAT ENI に向ける。/32 は不可なので専用サブネットを用意。

1 枚 ENI + ASG で常時 2 台

単一 ASG(desired=2, balanced-only)で各 AZ 1 台ずつ常時起動。SNAT はプライマリ ENI 1 枚。向け先 ENI が入れ替えで変わるため、ルートは Lambda が現用 ENI へ向ける。

なぜ /32 ではなくサブネット単位なのか VPC ルートテーブル(サブネット用もゲートウェイ用も)で ローカルルートより具体的なルートの宛先は 「サブネットの CIDR ブロック全体」に限られ、/32 や個別ホスト IP は指定できない (AWS::EC2::GatewayRouteTableAssociation)。よって VIP を含む /28 を空サブネットとして実在させ、その CIDR を現用 ENI へ向ける。

通信フロー

方向経路
送信クライアント → (クライアントRT) 現用 SNAT ENI → SNAT で送信元を .85 に固定 → (SNATサブネットRT, BGP伝播) VGW → VPN → ルーター → 接続先サーバー
戻り接続先サーバー → ルーター → VPN → VGW → (ゲートウェイRT) 10.10.0.80/28 → 現用 SNAT ENI → conntrack で逆変換 → クライアント
非対称ルーティング非サポート 送信(クライアントRT)と戻り(VGW ゲートウェイRT)は必ず同一の現用 ENIに揃える。フェイルオーバー時は両方を同時に付け替える。

フェイルオーバー(イベント駆動)

① イベント駆動の検知(停止 / 終了)

インスタンス停止/終了で EC2 Instance State-change Notification が数秒で発火 → Lambda。停止したインスタンスは describe に現れなくなり、秒単位で待機 AZ へ切り替わる。全件届くので Lambda 冒頭で自 ASG 以外は即 return。

② 詳細なヘルスチェックによる検知(経路破損)

「稼働しているが転送経路が壊れた」場合に備えた予備の検知。15 秒毎に ip_forward / SNAT ルール / 上流到達性(いずれもインスタンス固有の故障)を検査し FixedEgress/SnatPathHealthy を発行、AZ ごとに監視(欠損は breaching)。

③ ルート管理 Lambda

上記イベントと起動完了(launch)→ Lambda(Python, JSON ログ, 同時実行 1)。現用 AZ のインスタンス ENIへ RT を ReplaceRoute / CreateRoute。初回ルートは launch イベントで作る。

現用はできるだけ維持する(現用が正常 かつ 稼働中なら切り替えない。フラッピング防止)。待機系は常時起動なので、切り替えはルートの付け替えのみ。判定は「正常 かつ ENI が存在」なので、停止インスタンスは即 usable=false になり待機 AZ へ付け替わる。 source/dest 無効化は各インスタンスが userdata で自身に実施。現用 ENI が動的なため、送信 / 戻りルートの実体は CDK ではなく Lambda が管理する。
アラームが ALARM の AZ は、正常な対向 AZ があるとき異常なインスタンスを ASG 的に Unhealthy にして入れ替える(条件付きフェイルオーバー。両系 ALARM の全系障害では入れ替えず据え置く)。起動直後のインスタンスは ASG の grace period と起動からの経過時間で保護し、起動と入れ替えの繰り返しを防ぐ。

ルート切り替えが必要なシナリオと対応

シナリオ方式(トリガー)ルートの操作備考
現用 EC2 インスタンスの停止 EventBridge(EC2 状態変化 stopping)→ Lambda 待機 AZ へフェイルオーバー(秒) Lambda 内で停止された EC2 が SNAT(自 ASG)かどうか判定し、無関係なら即 return
現用 EC2 の終了(ASG 置換 / 障害 / stopping を経ない直接終了) EventBridge(EC2 状態変化 shutting-down)→ Lambda 待機 AZ へフェイルオーバー(秒) 停止と同じ経路。stopping / shutting-down の起点状態のみ購読(stopped / terminated は後追いで購読しない)
稼働しているが転送経路が破損(ip_forward / SNAT ルール / 上流到達不可) 詳細なヘルスチェック → CloudWatch アラーム → EventBridge → Lambda 待機 AZ へフェイルオーバー + 異常なインスタンスを入れ替え(1〜2 分) 状態変化イベントが出ないケース用の予備の検知。欠損は breaching。正常な対向 AZ があるときだけ異常なインスタンスを SetInstanceHealth で Unhealthy にして入れ替え(両系 ALARM では入れ替えない)
新インスタンス起動(自己修復 / 初回) EventBridge(EC2 Instance Launch Successful)→ Lambda 現用 AZ なら向ける / それ以外は現用を維持。初回はルート作成 ブートストラップ時は正常判定を待たず prefer AZ へ暫定で向ける
RT を置換するがインスタンスを作り直さないデプロイ 自動トリガーなし(launch イベントが出ない) 新しい RT が空のまま自動では張られない 既知の運用注意: ルート管理 Lambda を手動で 1 回実行して復旧する
待機インスタンスの入替 / 障害 AZ の復旧 各イベント → Lambda ルート変更なし(現用を維持) 不要な付け替え / 自動の切り戻しを避けフラッピング防止

全シナリオで実体は 同一の冪等な Lambda(同時実行 1 で直列化)。判定ロジックは共通: usable = アラーム正常 AND 当該 AZ にインスタンス ENI が存在 → 現用が usable ならそのまま維持(切り替えない)→ 不可なら prefer AZ → ルート 3 本(クライアント RT ×2 + VGW ゲートウェイ RT)を ReplaceRoute / CreateRoute。
※ ASG インスタンスを停止すると stopping(手動停止)に続き、ASG がそれを終了するため shutting-down も発火し Lambda は 2 回起動するが、2 回目は冪等な no-op(既に付け替え済み)。

デプロイ手順

# 依存 (pnpm 前提 / npx は使わない)
pnpm install

# 型チェック / テスト / 合成
node_modules/.bin/tsc --noEmit
node_modules/.bin/jest
node_modules/.bin/cdk synth

# デプロイ
node_modules/.bin/cdk deploy FixedEgressStack
userdata 変更は「再デプロイだけ」では効かない EBS ルートの EC2 は UserData 変更が Some interruptions(再起動) 止まりで、cloud-init は インスタンスにつき 1 回しか走らない。 新しい userdata を反映するにはインスタンスの作り直しが必要:
  • SNAT(ASG): インスタンスを終了 → ASG が最新起動テンプレートで再作成(確実)
  • ルーター / サーバー(CfnInstance): 論理ID変更などで強制置換

検証コマンド(SSM 経由): aws ssm send-command ... AWS-RunShellScript で /usr/local/bin/test-egress.sh を実行すると、接続先が見た送信元 IP(.85)が返る。

実機で判明した注意点

事象原因 / 対処
VIP を /32 で向けられないVPC ルートはサブネット CIDR 単位まで。VIP を含む /28 を空サブネットにして向ける。
VPN トンネルが両系 DOWNAL2023 に libreswan / frr が無い。IPsec は libreswan、BGP は spal-release 経由の frr を使う。親 IF は ens5。
SNAT ルールが作られないAL2023 に iptables / nft が無い。全サブネット public 化 → dnf install iptables-nft。
userdata を直しても反映されないEBS ルートは UserData 変更で再起動のみ。cloud-init は 1 回だけ。インスタンスを作り直す。
EIPAssociation が AlreadyExistsターゲット(instanceId)未指定の不正な関連付け。ENI / インスタンスを指定する。
VGW ゲートウェイルートテーブルの制約 propagation 有効だと関連付け不可 → propagation 無効の専用 RT にする。向け先 ENI は running インスタンスにアタッチ済みであること。別 AZ の ENI を向け先にする戻り疎通は仕様で明示されていないため要 PoC。
